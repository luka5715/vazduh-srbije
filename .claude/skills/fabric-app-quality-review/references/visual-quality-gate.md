# Visual fitness for the brief

Use this review for a new modern/premium experience or when the user says the result looks basic. Review the actual rendered artifact, the visual contract and the latest feedback. Aesthetic judgment is contextual; tie each conclusion to the brief and visible evidence. Do not turn taste into a fake objective score.

| Criterion | Evidence to inspect | Revision trigger |
| --- | --- | --- |
| Composition | Initial desktop view and main user question | Most regions have equal visual weight; generic card grid obscures the decision |
| Identity | Selected reference principles, typography and component treatment | Only the palette, corner radii, shadows or animation distinguish the result |
| Chart craft | Actual scales, labels, comparisons and marks | Decoration fills space; comparisons are hard to read; near-identical marks add no useful information |
| Typography | Rendered body, statuses, links and chart labels at actual scale | Most supporting information is tiny; long labels wrap awkwardly; metric size overwhelms context |
| Density and grouping | Full-page rhythm, shared surfaces and open space | Every section has identical card chrome; key information competes with filler or repetition |
| Mobile priority | First mobile view and path to the main action | Desktop is merely stacked; important actions sit several screens down; narrow columns fragment labels |
| Detail continuity | Entity/detail view and return path | Detail looks like another product or loses selected context |
| Motion | Initial state, changed state, interruption and reduced motion | Effects conceal a weak composition, delay data or leave an incorrect/stale state |

Apply relevant criteria only. Identical components can be intentional; a quiet enterprise design can satisfy a quiet brief. Do not mark a specific aesthetic as universally wrong. For a premium request, record Meets brief / Needs revision / Untested with the specific artifact and visible reason. Keep this distinct from Pass/Fail checks on data and interaction.

Compare revisions using the same viewport, data and state. If the second revision preserves a rejected composition and adds only features or effects, return the work to art direction before adding more polish. Use concrete alternatives such as regrouping the analytical surface, changing comparison encoding or reprioritizing mobile; avoid feedback limited to "make it pop".

Keep verification bounded: landing view, one meaningful filtered state, detail and mobile priority view are usually sufficient. Screenshot evidence supports visual judgments only. Static geometry/contrast scripts cannot verify art direction, rendered type quality or subjective appeal. Do not claim that updated instructions alone guarantee a better future output.
