# Art direction for analytics applications

## Convert the brief into visible decisions

Identify the main user decision, first-view priority, visual ambition and target surface before arranging components. Treat "spectacular" as a request for strong composition and identity, then substantiate it with visible choices. Avoid promising a subjective reaction.

For premium work, use two or three relevant reference views when available: one for composition, one for chart craft, one for interaction or mobile. Prefer the user's examples and supplied product assets. If browsing for references, inspect the source images and cite their actual sources; do not claim to have reviewed an unseen design. Extract principles rather than copying branding, logos or an entire screen. With no references, state a working direction and create local concept studies; do not stall for links.

Use the design-contract template. Record what will be visually distinctive and what will be removed. Adjectives such as clean, modern and premium are insufficient without a corresponding layout, typography or component decision.

## Explore composition before detail

For a new premium experience or a rejected generic design, render two small concept studies at the same viewport, with the same labels and dataset. Vary at least two structural choices: where the primary message sits, how comparison is presented, the relationship between analysis and actions, or how content is grouped. Light/dark variants of one layout do not count.

Possible starting compositions include:

| Direction | Organizing principle | Appropriate emphasis |
| --- | --- | --- |
| Editorial analysis | One main finding and large analytical canvas; contextual values sit with the chart; related detail uses open rows | Explaining performance to executives |
| Operational workbench | Prioritized work queue with persistent context and adjacent entity detail | Resolving exceptions and tracking delivery |
| Comparative atlas | Aligned comparison views on common scales; small supporting metrics and a focused inspector | Comparing entities, segments or scenarios |

Adapt these to the business question. They are not new presets to repeat universally. Choose a direction based on the brief, readability and information hierarchy. Continue with the selected option unless the user explicitly asked to choose first. Keep exploratory studies compact; develop one direction thoroughly.

## Give the design an identity

- Establish a display, section, body and metadata type hierarchy. For web mockups, start around 32–44 px for a page title, 13–15 px for body, and 12–14 px for labels, then inspect at actual rendered size. Reserve 11 px for genuinely secondary metadata. Choose large metric sizes in proportion to their importance. Map separately to native host units and verify Fit to page.
- Define open space and grouping before card styling. Use surface changes where they express structure; avoid repeating the same radius, outline and padding around every block.
- Choose one distinctive component treatment tied to the task: an integrated comparison, a carefully aligned diagnostic table, or a useful entity inspector. Do not substitute decorative orbs, glass effects and gradients for information hierarchy.
- Use consistent typography, units, label placement, icon family and chart semantics across landing, detail and mobile. An imported font is optional; confirm it loads or make the fallback equally intentional.
- Reorder mobile content around the first decision. Move secondary composition/rankings to an appropriate detail route or collapse them deliberately. A desktop page stacked into five screens of cards is not a mobile design. Preserve essential controls and context.

## Craft each chart for a question

For each chart state the question, encoding, scale, comparison and next action. Use the full available analytical area and remove marks with no useful discrimination. Near-identical 95% mini-bars are a poor comparison when their differences cannot be read; use a clear target comparison or a labeled trend instead. Do not truncate magnitude bars to exaggerate differences.

Do not default to a donut to fill a secondary card. Use it only when coarse composition is the actual question; use aligned bars or direct values for precise comparison. Sparklines show shape, not relative magnitude unless scales are shared. Label this distinction when needed. Prefer actual observations or honest interpolation; never invent a dramatic shape for visual effect.

Keep interactions consistent with analytical meaning. Hover should reveal useful detail. A transition should help track a change. Select an entity only when its selection opens detail or changes an intentional scope. Preserve units and comparison labels through filters.

## Critique the rendered result

Inspect initial desktop, a meaningful filtered state, detail and the mobile priority view. With animation disabled, the layout must still meet the brief. Compare with the chosen study and reference principles; identify concrete mismatches, not a self-assigned score.

If the user has rejected the look twice, stop adding features to the same scaffold. List the failed assumptions, produce a genuinely different composition, and retain only the data contract and working behaviors. Do not reuse a rejected design as a gold standard. Record the latest explicit feedback as acceptance criteria for the current task.
